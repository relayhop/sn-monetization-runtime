# Solution for Issue #895

## 🛠️ Proposed Solution (by Aditya Waghamare)

### Analysis
The issue points to a new math puzzle bounty item detected by the telemetry radar (`[Math Puzzle] Does every sequence terminate in a loop?`). To properly support parsing and handling math sequence loop termination problems in the `sn-monetization-runtime` ingestion pipeline, we need to add robust sequence analysis and cycle-detection utilities in Go.

### Fix
Add sequence parsing, validation, and cycle detection logic to `src/parser/bounty_parser.go`.

### Implementation
```go
package parser

import (
	"fmt"
	"strings"
)

// MathSequenceBounty represents a parsed math sequence puzzle bounty.
type MathSequenceBounty struct {
	ID         string
	Category   string
	Title      string
	IsHot      bool
	LoopFound  bool
	CycleLength int
}

// DetectLoop analyzes a numerical sequence (e.g. generated by a recurrence relation) to determine if it terminates in a loop.
func DetectLoop(sequence []int) (bool, int) {
	seen := make(map[int]int)
	for i, val := range sequence {
		if prevIndex, exists := seen[val]; exists {
			return true, i - prevIndex
		}
		seen[val] = i
	}
	return false, 0
}

// ParseMathPuzzleBounty parses raw telemetry strings for math puzzle bounties.
func ParseMathPuzzleBounty(raw string) (*MathSequenceBounty, error) {
	parts := strings.Split(raw, "\t")
	if len(parts) < 12 {
		return nil, fmt.Errorf("invalid math puzzle raw format: expected at least 12 columns, got %d", len(parts))
	}

	isHot := strings.Contains(parts[10], "HOT")
	return &MathSequenceBounty{
		ID:       parts[0],
		Category: parts[1],
		Title:    parts[11],
		IsHot:    isHot,
	}, nil
}
```
